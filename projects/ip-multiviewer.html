IP Multiviewer

Sources moved to IP faster than monitoring hardware could follow, and a fixed-function multiviewer costs more than it adapts. This ingests whatever the source speaks, transcodes it live, and puts it on a wall any workstation on the network can open.

The problem

When TOC adapted IP sources, purchasing an enterprise grade IP monitoring solution costs millions. Monitoring needed to cover sources that arrive over completely different transports — multicast off the plant network, contribution feeds over SRT, streams pulled from public platforms — and a hardware multiviewer handles one of those well and the rest not at all.

The build

A Node backend spawns and supervises an FFmpeg process per tile, normalises the output, and serves a browser wall that plays it back. Player libraries are served locally rather than from a public CDN, so the wall keeps working on a network with no route out.

  • Sources over UDP multicast and unicast, RTP, SRT, RTSP, RTMP and RTMPS, HLS and DASH, plus YouTube and Facebook live streams
  • Grid variants from 8 to 16 tiles for different monitoring positions
  • Per-tile audio metering through a single shared audio context pinned to one sample rate
  • Per-tile reinitialise for admins, persisted so it survives a restart
  • Directory authentication with a local fallback, role separation and audit logging

SCTE-35 visibility

Ad markers are invisible on a normal monitoring wall, which is exactly when you want to see them. Detection runs in two forms because the sources differ: manifest-based streams are polled for cue tags, while transport-stream sources get a binary parser reading splice information directly off the stream.

Raw splice data is not readable at a glance, so commands, descriptors and segmentation types are mapped to human names, and a gate suppresses the routine ones so the badge on a tile means something when it appears. Attributing a marker to the correct stream required discovering which streams carry splice data first, then relaunching with a dedicated parser attached to each one.

Set and forget

The design goal was a wall that survives being ignored. Every tile has a server-side watchdog with a stale threshold and a startup grace period, and a bounded number of restart attempts before it backs off rather than thrashing.

The governing principle throughout: a source failure shows as signal loss on one tile. It never takes the server down.

The outcome

The build allowed the company to save millions on purchasing an enterprise grade equipment with the same capability, or even more. Monitoring coverage extended to source types where no fixed-function device in the facility could do, at the cost of a workstation and the time to build it.
