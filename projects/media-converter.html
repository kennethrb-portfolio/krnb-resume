The problem

Conversion was done by hand, one job at a time, by whoever knew the right incantation. The results varied: wrong field order on an interlaced deliverable, loudness that failed the spec, a frame rate that was nearly but not exactly right. There was no queue, so two people converting at once fought for the same machine, and no record of what had been produced.

The knowledge lived in a handful of heads, which made it a bottleneck and a risk at the same time.

The build

A local web service wraps FFmpeg in a form that encodes the house rules. The critical decision was to populate the encoder and container options from the FFmpeg build actually installed on the machine, at boot — so the interface can never offer a codec the machine will then fail on.

  • Encoder and container options discovered from the installed FFmpeg at startup, not hardcoded
  • First-in-first-out job queue with live progress streamed to the browser
  • Field handling for interlaced and progressive deliverables, applied as an explicit choice
  • Rate control across constant-quality, variable and constant bitrate, with buffer constraints for compliant streams
  • Frame rate conversion using exact fractional rates rather than rounded approximations
  • Watch folder for automatic encoding, plus a directory browser and admin panel
  • Directory access confined to permitted paths, with every conversion logged

Getting the output broadcast-legal

The parts that decide whether a file passes QC are the ones with no visible symptom until it fails. Loudness runs as a two-pass measurement to the EBU R128 standard rather than a single-pass estimate, because a one-pass guess is what produces deliverables that measure correctly in isolation and wrong in a programme.

Sample rate handling had to account for the 48 kHz constraint on certain broadcast containers, and stream mapping had to be made explicit so that video, audio and subtitle tracks survive the container change instead of being silently dropped.

The outcome

Conversion stopped being a specialist task. An operator submits a job in a browser, the queue handles contention, and the output meets the delivery spec because the spec is built into the tool rather than remembered by the person running it.
