Regional Tape On Air
with Aspera Uploader

Proof of airing existed for material originating from one point. Regional stations had none — and covering each of them with a commercial system meant paying for the same capability many times over. This deploys the in-house Tape On Air solution to every regional site and moves what it records back to headquarters, so all of it is searchable from one place.

The problem

Regional stations had no recording of what they actually aired. When a discrepancy was raised — a spot queried, an outage disputed, a client asking what went out — there was nothing to check it against. The answer depended on whoever was on shift and what they remembered.

The obvious fix was the expensive one. Compliance recording is priced per site, and a network of regional stations multiplies that cost in a way a single origination point never does. Buying the same capability many times over, for sites that each need one channel of it, is a poor trade — which is how the gap stayed open.

The build

The in-house Tape On Air solution was already proven at headquarters, so the work was not building a recorder — it was getting that recorder to every regional site and getting the material back. Each station runs its own capture; an uploader built against the Aspera SDK moves the finished segments to headquarters, where they join the same archive and the same web front end everything else is previewed through.

  • Tape On Air deployed per regional site, recording from bootup with no operator action required
  • A watch-folder uploader picks up each completed recording segment and transfers it to headquarters over Aspera
  • Transfers run through the Aspera SDK rather than shelling out to a command-line client, so transfer state is observable rather than inferred
  • Every regional recording lands in the same archive as headquarters material and is previewed from one website
  • Monitoring-only interface showing connectivity, transfer activity and errors — paths and destinations stay in server-side configuration, not in the UI

Surviving an unattended site

A regional site has no one to restart anything. Whatever is deployed there has to assume it will be rebooted without warning, lose its link at the worst moment, and run for months with nobody looking at it. Every design decision followed from that.

  • Recording starts automatically at bootup, so a power event costs minutes rather than days
  • The uploader installs as a Windows service, so it survives crashes, reboots and logouts instead of depending on a signed-in session
  • Failed transfers are not discarded — they are tracked and re-queued, and drain automatically once connectivity returns
  • A file is only considered for transfer once it has stopped being written to, so the uploader never grabs a segment mid-write

The re-queue behaviour is the part that matters most in practice. Regional connectivity is not headquarters connectivity, and an uploader that simply fails during an outage produces exactly the gap the whole system exists to prevent.

The outcome

Every regional station now has proof of airing, at a fraction of what per-site commercial coverage would have cost. Disputes and recording enquiries that previously had to be chased through individual stations are answered from one place, by whoever picks up the request — without a call to the region and without waiting for someone there to go looking.
